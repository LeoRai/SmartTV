# Профили ротации и язык условий

Всё, что меняется от патча к патчу, лежит в `ForeverCoach/Data/`. После патча правятся эти таблицы, код не трогается. Проверка: `lua5.1 tools/validate_profiles.lua`.

## Заклинания: `Data/Spells/<Класс>.lua`

Только ID: названия и иконки отдаёт клиент, поэтому в русской игре всё сразу на русском.

```lua
corruption = {
    role = "dot",                  -- filler, dot, curse, drain, execute, cc, defense, cooldown,
                                   -- pet, buff, summon, utility, wand, aoe
    source = "trainer",            -- trainer, quest, talent, class, book
    cast = 2.0,                    -- запасное время каста (клиент знает точнее)
    duration = { 12, 15, 18 },     -- дебафф на цели, по рангам (последнее значение для старших)
    ranks = { {172, 4}, {6222, 14}, {6223, 24, "trainer"} },  -- {ID, уровень, источник?}
},
```

Остальные поля: `channel`, `cooldown`, `gcd = false` (вне ГКД), `buff` (вешает бафф на себя), `consumes` (тратит прок), `requires` (нужен свой дебафф), `talent`, `pet` и `petFamily` (способность демона), `wand`, `harmful` (нужна враждебная цель; для боевых ролей включено само).

В том же файле: `buffs` (баффы на себе; `glow` — заклинание, которое клиент подсвечивает при проке), `talents` (ID рангов), `items` (ID от лучшего к худшему), `pets` (призыв и названия семейства на enUS/ruRU).

## Профиль: `Data/Profiles/<Класс>_<Билд>_<Режим>.lua`

```lua
ns.Data:DefineProfile("WARLOCK", function()
    return {
        id = "Warlock_Affliction_Leveling",   -- <Класс>_<Билд>_<Режим>
        build = "Affliction", mode = "leveling",   -- leveling | group | pvp
        version = "0.1.0", patch = "1.60.1", date = "2026-11-11",
        talents = { nightfall = 1, siphon_life = 1 },  -- ключевые таланты билда
        approximate = false,                 -- true для общих правил класса
        aoe = true,                          -- метка «AoE · N врагов» от 3 врагов

        main     = { { "corruption", "debuff.corruption.refreshable & target.ttd > 8", why = "WHY_DOT" }, ... },
        defense  = { { "healthstone", "player.hp_pct < opt.hp", why = "WHY_HEALTHSTONE" }, ... },
        cooldown = { { "amplify_curse", "target.boss | target.elite", why = "WHY_AMPLIFY" }, ... },
        prep     = { { "!pet.exists & known.summon_imp", text = "PREP_NO_PET" },
                     { "trainer > 0", text = "PREP_TRAINER", value = "trainer", place = "trainer" }, ... },
    }
end)
```

- Строки проверяются сверху вниз. Побеждает первое **доступное** действие, чьё условие выполнено.
- **Доступно** — значит выучено (берётся старший ранг), нет отката (или он кончится к концу ГКД), клиент считает заклинание применимым (мана, требования), есть враждебная цель для боевых заклинаний, нужный демон для его способностей, жезл для «Выстрела». Цель вне радиуса допускается, только если в радиусе ничего не подошло, тогда иконка красная.
- `main` — главная иконка и следующие 0–3 (прогноз, по умолчанию 3). `defense` — слот слева, `cooldown` — слот справа. `prep` — строка подготовки вне боя: показывается первое сработавшее условие. `value` — путь к числу для `%d` в тексте, `place = "trainer"` — дописать город учителя («· Брилл»).
- `why` — ключ текста в `Locales/*.lua`, этот текст показывается при наведении на иконку.
- `gate = { unit = "player" | "target" | "pet", below = 35 или "hp" / "pet_hp" }` — **ворота по здоровью**: строка действует, только пока здоровье этой цели не выше порога (число в процентах или ключ настройки `opt`). Если здоровье видно, движок проверяет его сам. В Forever оно скрыто всегда, поэтому строка уходит из обычного выбора и показывается наложением: Похищение души поверх главной иконки, защита и помощь демону — на слоте защиты. Видимость решает клиент по скрытому здоровью (`API.BindHealthGate`). Обычное условие строки (осколки, есть ли камень) движок проверяет как всегда.
- Пустое условие `""` — «всегда».

Подбор профиля: `<Класс>_<Билд>_<Режим>`, затем `<Класс>_Generic_<Режим>`, затем `<Класс>_<Билд>_Leveling`, затем `<Класс>_Generic_Leveling`. Всё, кроме первого, помечается как «приблизительный».

## Язык условий

Приоритет операторов от слабого к сильному: `|` → `&` → `!` → сравнения → `+ -` → `* /` → унарный `-`. Есть скобки. Также работают `and`, `or`, `not`, `&&`, `||`, `==`, `!=`, `~=`. Логические значения в арифметике — 1 и 0, число истинно, если не 0. `!a > 3` означает `!(a > 3)`.

| Переменная | Значение |
|---|---|
| `player.level`, `player.hp_pct`, `player.mana_pct`, `player.mana` | уровень, здоровье %, мана %, мана |
| `player.in_combat`, `player.moving`, `player.casting`, `player.dead` | состояние |
| `player.oom` | наполнитель неприменим из-за маны (работает, даже когда мана скрыта) |
| `combat` | то же, что `player.in_combat` |
| `target.exists`, `target.enemy`, `target.hp_pct`, `target.ttd` | цель, враждебна, здоровье %, секунд до смерти |
| `target.boss`, `target.elite`, `target.player`, `target.in_range` | тип цели и дистанция |
| `pet.exists`, `pet.hp_pct`, `pet.<семейство>` | демон: `pet.voidwalker`, `pet.imp`, ... |
| `debuff.<ключ>.up / down / remains / refreshable / stack` | свой дебафф на цели. `refreshable` — осталось меньше времени каста + 0,5 с |
| `buff.<ключ>.up / down / remains / stack` | бафф на себе (`shadow_trance`, `armor`) |
| `cooldown.<ключ>.ready / remains` | откат заклинания |
| `known.<ключ>` | заклинание выучено (любой ранг) |
| `talent.<ключ>` | ранг таланта, 0 — не взят |
| `item.<ключ>.count / ready` | предмет в сумках и готов |
| `last.<ключ>` | секунд с последнего применения (999 — не применялось) |
| `gcd.remains`, `gcd.duration` | глобальный кулдаун |
| `enemies` | враги рядом (по индикаторам здоровья, нужно включить вражеские индикаторы) |
| `soul_shards` | осколки души в сумках |
| `trainer` | сколько рангов ждёт у учителя |
| `mode.leveling / group / pvp` | текущий режим |
| `opt.hp`, `opt.pet_hp`, `opt.shards` | пороги из настроек: Камень здоровья, Канал здоровья, осколки души |

В прогнозе (2-я, 3-я и 4-я иконки) переменные считаются на момент, когда до действия дойдёт очередь: дебаффы уже повешены, откаты запущены, прок потрачен, `target.ttd` уменьшился.

### Когда игра скрывает значение

| Значение | Допущение |
|---|---|
| `player.hp_pct`, `pet.hp_pct`, `target.hp_pct` | 100 (пороги по здоровью — через `gate`) |
| `player.mana_pct` | 100 (для «нет маны» есть `player.oom`) |
| `target.ttd` | 999 (цель живёт долго) |
| дебаффы на цели | свои таймеры от кастов |
| откаты, ГКД, текущий каст | свои таймеры от кастов |
| баффы на себе | свои таймеры. Проки — по подсветке заклинания клиентом |

Допущения выбраны так, чтобы скрытое значение не вызывало ложных тревог. В `/fc debug` такое значение помечено `*`.

## Новый класс

1. `Data/Spells/<Класс>.lua` через `ns.Data:DefineClass("<TOKEN>", function() return {...} end)`.
2. `Data/Profiles/<Класс>_Generic_Leveling.lua` и профили топ-3 билдов Talents Forever.
3. Файлы добавить в `ForeverCoach.toc` после `Data\Spells\Warlock.lua`.
4. `lua5.1 tools/validate_profiles.lua` и `busted`: сценарии класса в `tests/`.
